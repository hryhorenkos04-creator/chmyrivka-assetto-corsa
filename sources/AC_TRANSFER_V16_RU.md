# v16 — перенос текущих материалов в отдельный тестовый сектор

## Назначение и граница результата

Цель этого прохода — получить исправленный нативный сектор **из текущей художественной сцены v16** и отдельно перенести в изображения материал шести домов у камер обзора. Полный сектор — картографические 3800–4250 м Сінної с окружением до 100 м от оси. Это не утверждение, что весь сектор или вся трасса уже переведены на игровые материалы.

Сборка и проверки завершены. Фактический результат подтверждается `transfer/chmyrivka_sinna_native_v16.validation.json`, `transfer/baked_work/bake_report_v16.json` и `transfer/audit_bake_v16.json`. Ни KN5, ни ksEditor, ни Assetto Corsa в этой среде не запускались.

## Исправленная вырезка

Каждый материал evaluated-меша сначала разрешается в постоянный `.original` ID и только затем присваивается сохраняемому объекту. Полигональные индексы не перезаписываются при переносе произвольных атрибутов. После освобождения временных мешей, сохранения и повторного открытия проверяются:

- последовательность материалов на всех гранях;
- хеши графов материалов;
- все исходные UV-массивы;
- координаты, индексы вершин граней, размеры и порядок граней, smooth flags вырезанных мешей;
- неизменность исходного файла v16.

Геометрия берётся целыми гранями по их центрам, поэтому у сектора приблизительные открытые торцы. У основного ground-меша нормали пересчитываются по тем же граням: это унаследованный обход сбоя custom-normal setter в bpy 4.5.7, а не утверждение о точном сохранении его custom normals. Изменённая обрезкой область ограничивающего параллелепипеда и новый объект могут влиять на неперенесённые материалы с Generated/Object/Random координатами; графовая идентичность сама по себе не доказывает пиксельное совпадение таких процедурных материалов.

## Изображения и масштаб

Используется реальное запекание Cycles CPU: Base Color через EMIT без освещения, Roughness как линейный scalar через EMIT, Normal в tangent-space с осями +X/+Y/+Z. Исходные неявные ссылки UV фиксируются на исходной именованной UV-развёртке до создания атласа. Новая развёртка `V16_Atlas` становится UV0; все прежние UV-слои сохраняются.

Целевая плотность стен — 128 px/м, крыш — 64 px/м; размер мастер-атласа 4096 × 4096. Отступ при запекании — 12 px, рамка острова — 16 px. Число атласов и реальные размеры записаны только по завершённой сборке в отчёте. Изображения — PNG-мастера, не готовые сжатые DDS.

При 128 px/м размер одного пикселя около 7,8 мм: **поры 2–5 мм в такие карты достоверно не помещаются**. Этот проход переносит кладку, раствор, более крупную неоднородность и следы эксплуатации. Для близкого игрового вида понадобится отдельный повторяемый слой мелкой normal-текстуры и проверка mip-уровней. Нельзя просто увеличивать силу нормали и считать потерю частот исправленной.

## Связь с игровыми материалами

| Мастер-канал | Что сохранено | Что ещё необходимо |
|---|---|---|
| Base Color | цвет материала без тени и прямого света | проверить цвет и экспозицию под игровым освещением |
| Normal | направление нормалей в tangent-space, +X/+Y/+Z | проверить тангенты, ориентацию каналов и силу выбранного шейдера в ksEditor |
| Roughness | исходный пространственный параметр Blender | подобрать и проверить отражение в модели игрового шейдера; это не автоматическое значение `ksSpecularEXP` |
| Прочие скаляры Principled | исходные константы для текстурного просмотра в Blender | не объявляются автоматически совместимыми с Assetto Corsa |

Шейдеры AC здесь не назначаются. Процедурные ветви остальных материалов не заменяются постоянным цветом ради формального экспорта. При переносе выбранного шейдера надо проверить фактический комплект SDK и его параметры; ранее созданный FBX v14 содержит старые изображения и не представляет новую v16.

## Воспроизведение

Из корня каталога v16, в Python с bpy 4.5.7, NumPy, Pillow, Shapely и SciPy:

```text
python transfer/extract_sector_v16.py --source chmyrivka_visual_v16.blend --target transfer/chmyrivka_sinna_native_v16.blend --route transfer/data/track_plan_v08.json
python transfer/bake_cohort_v16.py --source transfer/chmyrivka_sinna_native_v16.blend --out transfer/baked_work
python transfer/validate_bake_v16.py --report transfer/baked_work/bake_report_v16.json --out transfer/audit_bake_v16.json
```

Общие тяжёлые bpy-процессы сериализуются через `/tmp/chmyrivka_v16_bpy.lock`. Входные файлы v13/v14/v15/v16 не перезаписываются. Источники методов: официальный [Blender Manual — Render Baking](https://docs.blender.org/manual/en/4.5/render/cycles/baking.html), исходные рабочие процедуры v14, исправление evaluated Material ID v15. Карта: © OpenStreetMap contributors, ODbL; лицензии исходных изображений, их метаданные и атрибуция высот включены в `transfer/sources/` из основного комплекта.
