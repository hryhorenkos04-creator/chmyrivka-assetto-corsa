# Экспорт в Assetto Corsa — рабочий комплект

Цель прохода: **довести сцену v17 до первого проезда в игре.** Это не художественный проход и не релиз мода. Задача — узнать, едет ли построенная геометрия вообще.

## Что проверено, а что нет

**Проверено фактическим прогоном** на сцене `chmyrivka_visual_v17.blend` (SHA `06ccd62b…fabdafd22`), Blender 5.3, оба режима:

| Показатель | `sector` | `full` |
|---|---:|---:|
| Время экспорта | 16 с | 35 с |
| Объектов в FBX | 559 | 6032 |
| Отсеяно декора | 5473 | 0 |
| Получили коллизию | 266 | 266 |
| Остались визуальными | 293 | 5876 |
| Текстур выгружено | 24 | 24 |
| Размер FBX | 110 МБ | 235 МБ |
| Пиковая память | ~2 ГБ | ~3,2 ГБ |

Секций `1KERB_` в FBX ровно **33** — сходится с заявленными 33 секциями поребриков. Все четыре пустышки `AC_START_0`, `AC_PIT_0`, `AC_TIME_0_L`, `AC_TIME_0_R` на месте.

**Не проверено ничем:** ksEditor, сборка KN5, запуск в игре, физика поверхностей, ориентация спавна, производительность. `assetto_corsa_tested` остаётся `false` до первого фактического проезда.

## Важно: ловушка с текстурами

Все 25 изображений **упакованы внутрь** `.blend` — внешних файлов сцене не нужно. Но каждое изображение сохранило путь, по которому его когда-то импортировали: `//../chmyrivka_detail_v13/textures/…`. Этой папки нет ни в репозитории, ни в релизе.

Штатный экспорт FBX идёт по этому пути, файла не находит и **молча выбрасывает все текстуры**. В логе это выглядит как `missing '…', not copying`, а на выходе — геометрия без единой карты.

Скрипт обходит это: берёт упакованные байты напрямую из `packed_file.data`, пишет их рядом с FBX и перенаправляет ссылки. Перекодирования нет, файлы выходят ровно те же, что скачивались с Poly Haven и ambientCG.

Если будете экспортировать вручную через меню Blender — сначала `File → External Data → Unpack Resources`, иначе получите серую сцену.

## Что уже готово в сцене

Серёга назвал две главные поверхности по конвенции AC ещё при сборке:

| Объект | Роль |
|---|---|
| `1ROAD_MAIN` | основное гоночное полотно |
| `1PIT_SURFACE_V08` | покрытие пит-лейна |

Ведущая `1` в имени меша — это метка «у объекта есть коллизия», а дальше идёт `KEY` из `surfaces.ini`. Остальные поверхности — рельеф, обочины, поребрики, боковые дороги — этой метки не имеют, поэтому машина сквозь них провалится. Скрипт экспорта проставляет префиксы им всем.

## Что нужно

- **Blender** — сцена собрана в 4.5.7. Ветка 5.x её тоже откроет. **Не сохраняйте сцену в новой версии:** обратной совместимости у Blender нет, исходник Серёги после этого не откроется в 4.5.
- **Assetto Corsa** + официальный **SDK** с `ksEditor` (только Windows).
- **Content Manager** — не обязателен, но на порядок удобнее штатного лаунчера.
- Сцена `chmyrivka_visual_v17.blend` из [релиза v17](https://github.com/hryhorenkos04-creator/chmyrivka-assetto-corsa/releases/tag/v17). SHA-256 архива: `eab02b9e98d1e292aa07151f29ec03036a0321b936348797bcf7828ee6da6ed3`.

## Шаг 1. Экспорт FBX

Скрипт открывает сцену **только на чтение** и никогда её не сохраняет. Переименования живут в памяти процесса и до файла Серёги не доходят.

```bash
blender --background --python ac_export/export_ac_v17.py -- \
    --scene /путь/к/chmyrivka_visual_v17.blend --mode sector
```

Режимы:

- `--mode sector` — **начните с него.** Полный круг всех ездовых поверхностей плюс окружение только возле участка 3800–4250 м, который доведён художественно. Файл небольшой, итерация быстрая, круг при этом проезжается целиком.
- `--mode full` — вся сцена. 6028 мешей без LOD, AC это переварит плохо. Только когда sector уже поехал.

На выходе в `ac_export/out/`:

- `chmyrivka.fbx` — геометрия;
- 24 файла текстур **рядом с FBX**, не в подпапке: экспорт обрезает пути до коротких имён, и ksEditor ищет их в папке самого FBX;
- `export_report.json` — полный список переименований, что отсеяно, какие текстуры выгружены.

Папка в Git не попадает, она в `.gitignore`.

Небо `kloofendal_…_4k.hdr` намеренно не выгружается: это освещение сцены Blender, у AC своё небо. Нужно — добавьте `--keep-hdr`.

Полезные ключи:

| Ключ | Зачем |
|---|---|
| `--start-station 3800` | где ставить старт, в метрах исходной карты |
| `--flip` | если машина появилась задом наперёд |
| `--corridor 120` | ширина коридора отбора окружения, м |
| `--sector-from / --sector-to` | границы участка |

## Шаг 2. Карта поверхностей

Скрипт раздаёт префиксы по имени объекта:

| Было | Стало | Поверхность |
|---|---|---|
| `1ROAD_MAIN` | без изменений | ROAD |
| `1PIT_SURFACE_V08` | без изменений | PIT |
| `ROAD_SHOULDERS` | `1ROAD_…` | ROAD |
| `SIDE_ROADS*` | `1ROAD_…` | ROAD |
| `V08_Racing_kerbs*`, `V15_KERB*` | `1KERB_…` | KERB |
| `VERGE_Grass_*` | `1GRASS_…` | GRASS |
| `VERGE_Gravel_*` | `1DIRT_…` | DIRT |
| `GROUND_land_industrial` | `1DIRT_…` | DIRT |
| `GROUND_*` (рельеф, зоны) | `1GRASS_…` | GRASS |
| всё остальное | без префикса | только визуал |

Дома, деревья, заборы коллизий намеренно не получают. Так и надо для первого проезда: врезаться пока не во что, зато ничего не ломает физику и не жрёт процессор.

## Шаг 3. Точки появления и створ

Скрипт строит четыре пустышки по гоночной оси v15 (11 475 точек в `data/inherited_racing_v15/racing_line_native_v15.json`):

- `AC_START_0` — стартовая клетка
- `AC_PIT_0` — бокс, в 12 м позади старта
- `AC_TIME_0_L` / `AC_TIME_0_R` — створ старт-финиша, по умолчанию 14 м

**Ориентация пустышек — главное место, где можно промахнуться.** Я задаю разворот по касательной к гоночной оси, но как именно AC читает эту ориентацию из FBX — надо проверить в игре. Если машина появится задом наперёд, перезапустите с `--flip`. Это нормальный рабочий цикл, а не поломка.

## Шаг 4. ksEditor

1. Открыть `chmyrivka.fbx`.
2. Назначить шейдеры. Для первого раза хватит `ksPerPixel` на всё; для полотна можно `ksPerPixelMultiMap`. Тонкая настройка — потом.
3. Проверить, что текстуры подхватились из папки рядом с FBX.
4. Сохранить `chmyrivka.kn5`.

Процедурные материалы Blender (щебень, песок, Grass001) в FBX не переносятся — на их месте будет пусто. Это ожидаемо: для себя достаточно назначить ближайшую понятную текстуру вручную.

## Шаг 6. Проезд

Одиночная сессия, практика, одна машина. Проверять по порядку:

- [ ] трасса вообще появилась в списке
- [ ] машина появилась на дороге, а не под ней и не в воздухе
- [ ] машина стоит по направлению движения
- [ ] дорога держит — нет проваливания
- [ ] нет щелей и ступенек на стыках полотна
- [ ] обочина и трава ощущаются как разные поверхности
- [ ] поребрики работают и стоят осмысленно
- [ ] круг засчитывается при пересечении створа
- [ ] проезжается весь круг без тупиков
- [ ] частота кадров пригодна для езды

Записать: конфигурацию ПК, настройки графики, время кадра. Снять игровые кадры — **это будут первые изображения проекта не из Blender.**

## Что заведомо вылезет

**Геометрия.** Проектная линия считалась для абстрактной коробки 5×2 м с запасом 0.2 м. Живая машина поведёт себя иначе. Узкие повороты и неудобные связки — ожидаемы, это правится в сцене.

**Стыки.** Полотно строилось процедурно по картографическим линиям. Микрощели между сегментами в рендерах не видно, а в игре это удар подвески.

**Рельеф.** Copernicus GLO-30 — спутниковая модель высот, не дорожная съёмка. Продольные уклоны могут не соответствовать реальным.

**Производительность.** 6028 мешей, LOD нет, окклюзии нет. В режиме `full` ждите просадок.

**Чего здесь нет вообще:** AI-линии (`fast_lane.ai`), нескольких боксов, границ трассы для штрафов, звуковых зон, камер трансляции, времени суток. Всё это не нужно, чтобы проехать.

## Как сообщать о проблемах

Геометрию может чинить только тот, у кого сцена — то есть Серёга. Чтобы отчёт был полезен, указывайте:

1. **метр по исходной карте** — он есть в названиях объектов `VERGE_*` и в `MAP_AUDIT_RU.md`;
2. скриншот из игры;
3. что именно не так: провал, щель, узко, упирается.

Привязка к метражу важнее всего: по ней он найдёт место в сцене за секунды, по словесному описанию — за час.
